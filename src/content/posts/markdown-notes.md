> 示例文章，同时用于展示 Markdown 正文的排版效果。

## 从一个清楚的问题开始

打开一份空白文档时，不必立刻写出漂亮的开头。先写三个问题：我要解决什么？我试过什么？最后学到了什么？

这三个问题，通常就能形成一篇技术笔记的骨架。

## 先写结构，再补细节

Markdown 的标题可以直接表达文章的层次：

```markdown
# 文章标题

## 问题背景
描述具体的使用场景。

## 解决过程
记录关键的步骤和选择。

## 后续思考
保留尚未解决的问题。
```

在这个博客里，文章标题来自文件顶部的 `title` 字段，所以正文从二级标题 `##` 开始即可。

### 用代码块保留上下文

代码块不仅可以复制，也能准确记录当时执行的操作。给代码块标注语言，还可以获得更清楚的语法高亮。

```typescript
const notes = ['观察', '尝试', '记录'];

for (const note of notes) {
  console.log(`今天的一小步：${note}`);
}
```

### 用列表整理并列的信息

- 尽量在一个段落里只解释一个想法。
- 给代码保留必要的背景。
- 在结论旁边写下它成立的条件。
- 对暂时没理解的部分做一个标记。

## 保留修改的空间

文章发出去之后，仍然可以更新。发现更好的表达方式，就再改一遍；遇到新的例子，就补充进去。

> 写作不是一次性交付，而是持续整理自己理解的过程。

让工具退到后面，把注意力留给正在思考的问题。
